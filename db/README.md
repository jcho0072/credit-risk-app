# Database Management & Migration Plan

This directory contains the SQL assets for the Credit Risk Assessment System.

## Current Schema Issues (db/schema.sql)
1. **Dialect Confusion**: The current `schema.sql` contains a mix of Oracle (`NUMBER`, `VARCHAR2`) and PostgreSQL (`SERIAL`, `NUMERIC`) syntax. This causes issues depending on the deployment environment (Render uses PostgreSQL).
2. **Scratchpad State**: The file is heavily commented out and contains a mixture of DDL (table creation), DML (inserts), and analysis queries. It lacks a clear "source of truth" for the production schema.
3. **Naming Inconsistency**: The database uses `Financials` and `person_id`, while the project roadmap (`TODO.md`) calls for `LoanApplication` and `application_id` to better reflect that records are application snapshots.
4. **Lack of Data Integrity**: There are no SQL-level `CHECK` constraints (e.g., ensuring age > 18 or income >= 0) or Foreign Key relationships in the dimensional model.
5. **Redundant Tables**: Tables like `temp`, `credit_data`, and `financials` overlap in purpose, leading to data synchronization risks.

## Migration Plan (`migrations.sql`)

The following steps will be implemented in `migrations.sql` to standardize the database:

### Step 1: Standardize Core Domain
- **Action**: Rename `financials` table to `loan_applications`.
- **Action**: Rename `person_id` column to `application_id`.
- **Goal**: Align the database with the updated domain terminology.

### Step 2: Data Integrity & Constraints
- **Action**: Add `CHECK` constraints for:
    - `person_age` (>= 18)
    - `person_income` (>= 0)
    - `loan_amnt` (> 0)
- **Goal**: Enforce business rules at the database level.

### Step 3: Identity Refactoring
- **Action**: Ensure `application_id` uses an auto-incrementing identity (e.g., `GENERATED BY DEFAULT AS IDENTITY` in Oracle or `SERIAL` in PostgreSQL).

### Step 4: Analytical Warehouse (Star Schema)
- **Action**: Formalize the creation of:
    - `ApplicantDIM`: Demographic data.
    - `LoanDIM`: Intent and Grade data.
    - `RiskDIM`: Historical default and credit history.
    - `LoanFact`: The central fact table for analytical reporting.
- **Goal**: Enable efficient business intelligence and risk reporting.

## Missing Files (Recommended)
Based on standard database architecture, we should also include:
1. **`seeds.sql`**: Initial data to populate the warehouse and testing environments.
2. **`views.sql`**: Pre-defined analytical views (e.g., `loan_grade_summary`) to simplify reporting queries.
